## Key Decisions

| Decision | Rationale |
|----------|-----------|
| Raw Telegram Bot API via httpx, not aiogram | Only sendMessage needed; fewer deps. Switch to aiogram if bot commands are added |
| RSS first, then API, HTML scraping last | Most stable, least ban risk |
| No auto-replies to orders | Violates exchange ToS; user responds manually |
| Upwork: only official API, no scraping | Scraping explicitly banned by ToS |
| Config via `.env` + dataclass (no pydantic) | Minimal deps |
| Sources as `Protocol` | New source = class with `name` + `async fetch()` |

```python
@dataclass(frozen=True)
class Order:
    source: str; id: str; title: str; url: str
    description: str = ""; budget: str = ""

class Source(Protocol):
    name: str
    async def fetch(self) -> list[Order]: ...

async def poll_once(sources, matches: Callable[[Order], bool], storage: Storage, notifier | None) -> None
Storage.add_if_new(order) -> bool   # True only on first insert (INSERT OR IGNORE)
```

Non-obvious: `KeywordFilter` with empty keywords passes everything not stop-listed; stop-words checked first. RSS `Order.id` falls back to link if no guid. Orders are stored as seen even if Telegram send later fails (send raises after insert).

## Edge Cases & Error Handling

- Source HTTP error → logged, other sources continue
- Telegram send error → exception propagates and kills the loop; order already marked seen (not handled yet)
- Malformed `RSS_FEEDS` entry without `=` → url becomes empty string (not validated)
